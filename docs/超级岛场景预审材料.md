# 超级岛场景预审材料（草稿）

> 用途：提交小米开发者后台「超级岛」申请时的上岛场景预审材料。
> 本文对应官方接入流程第 2 步「申请开通超级岛 → 提交上岛场景预审材料」。
> 提交前请按官方后台最新模板调整格式（本稿保留全部应答要点）。

---

## 1. 应用基本信息

| 项 | 内容 |
|---|---|
| 应用名称 | 节律岛（islandTimer） |
| 包名 | com.hsh.islandtimer |
| 一句话定位 | 在前台使用指定应用时，于超级岛实时显示「今日累计使用时长」的轻量计时工具 |
| 目标模板 | 官方模板库「计时器 / 进度条」类 |
| 展示形式 | 进入被计时应用：大岛展示 2–3 秒 → 折叠为胶囊显示 `⏱ 12:34`；退出到桌面或息屏：立即消失 |
| 鉴权方式 | 客户端原生通知通道 + 指纹证书 + APP_ID |

## 2. 上岛场景描述（核心应答）

**触发条件**：用户预先在应用内勾选的「被计时应用」（如抖音、B站、微信读书）进入前台。

**展示内容**：
- 进入瞬间：大岛显示「应用名 + 今日累计时长」，2–3 秒后自动折叠；
- 折叠态：胶囊显示计时图标 + `HH:MM`（分钟级更新，15 秒节流刷新）；
- 内容为**该应用今日累计使用时长**（跨会话累加，每日零点清零，另有每周汇总）。

**消失条件**：
- 被计时应用退到后台 / 回到桌面 → 立即停止计时并撤下通知（岛消失）；
- 息屏 / 锁屏 → 立即停止计时并撤岛；
- 切换到未勾选应用 → 立即撤岛。

**为何不是常驻占岛**：本应用的上岛生命周期与被计时应用的前台状态严格绑定——应用在岛才在，应用退岛即消，不存在无场景的空占岛状态；息屏也会主动撤岛。最长单次上岛等于用户单次前台使用时长，属「计时器」模板的预期行为。

## 3. 无障碍服务用途说明（审核重点）

- 唯一用途：监听 `TYPE_WINDOW_STATE_CHANGED` 窗口事件，获取当前前台应用包名，用于判定「被计时应用进入/退出前台」的瞬时触发；
- **不读取屏幕内容**（`canRetrieveWindowContent = false`）；
- **不执行任何模拟点击 / 滑动 / 输入操作**；
- 已实现「仅 UsageStats 的降级模式」代码空间：用户拒绝开启无障碍时，应用仍可基于使用情况访问权限做分钟级统计，无障碍仅作为可选的响应加速；
- 所有统计只在本机处理，不上传任何使用数据。

## 4. 权限清单与理由

| 权限 | 用途 |
|---|---|
| 使用情况访问（UsageStats） | 权威账本：跨天历史校准、对账，保证时长准确 |
| 无障碍服务 | 前台应用切换的亚秒级检测（不读内容、不模拟操作） |
| 前台服务（specialUse） | 计时进行中的常驻通知载体（即上岛通知） |
| 忽略电池优化请求 | 仅引导用户自行设置，保证后台检测不中断 |
| 通知 | 上岛通知展示 |

## 5. 审核风险点自答（提前准备）

1. **「常驻时长边界」**：岛上展示的计时与被计时应用前台状态实时绑定，进则显、退则消、锁屏即撤，折叠胶囊只展示 `⏱ HH:MM` 极简内容，不属于常驻占岛。
2. **「无障碍正当性」**：见 §3；可随时在应用内关闭无障碍，功能自动降级为 UsageStats 分钟级统计。
3. **「指纹证书稳定性」**：从申请之日起使用固定正式签名（release.keystore），保证「指纹证书 + APP_ID」鉴权长期有效；后续升级 APK 不改签名。

## 6. 上岛资源规格（待联调）

- 单图 ≤ 100KB、HTTPS、宽高比 1.78:1（16:9）~ 1:1；
- 图标：计时沙漏/秒表风格 smallIcon（已内置 `ic_timer`）；
- 样式严格遵循官方「超级岛模板库」计时器模板；`miui.focus.*` 富样式字段以官方联调文档为准（代码中 HyperIslandHelper 已预留接入位）。
